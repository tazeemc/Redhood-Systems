# RedHood Systems — May 2026 Audit Notes

## Why this audit existed

The pbix you uploaded showed one report page with a single `tableEx` listing
hypothesis text against a run-date hierarchy — no slicers, no measures
beyond implicit aggregation, no ticker- or side-aware analysis. The
underlying SQLite model already had rich per-narrative attributes
(`bear_case`, `disconfirming_signals`, `conviction_adjustment`, entropy
band, catalyst count) and the `powerbi/` directory already shipped a
clean export pipeline + DAX measures + a 5-page report layout. So the
report layer was further along than it looked from the pbix alone — the
pbix is a stub against the documented design.

The real workflow gap was upstream of the report: tickers and direction
(long / short) live as free text inside the `hypothesis` column, so
"which tickers keep showing up as longs?" wasn't answerable in the
model. Without that, the "add to winners" workflow you wanted couldn't
be served, and a $2,500-sized P&L per recurring long was uncomputable.

## What this audit added

**New modules**
- `redhood_grader.py` — pure-stdlib parser. Extracts long-side equity /
  ETF tickers from a hypothesis (filters out shorts, futures, options,
  forex, bonds, ratio denominators) and applies a 0–20 quality grade
  across four axes: Specificity, Catalyst, Risk Management, Cohesion.
  Letter grade A–F. Run `python redhood_grader.py --self-test` to
  verify against 17 representative hypotheses.
- `redhood_pnl.py` — yfinance-based P&L tracker. Reads
  `narrative_tickers`, fetches historical closes (cached in `prices`
  table), and computes P&L on a $2,500 standard sizing. Optional
  dependency — the rest of the codebase works without it.
- `score_narratives.py` — CLI that walks every row in `narratives`,
  grades it, and persists results to `narrative_tickers` +
  `narrative_grades`. Idempotent — safe to re-run.

**Schema additions (`models.py`)**
- `narrative_tickers (narrative_id, ticker, side, is_long_equity, extracted_at)`
- `narrative_grades  (narrative_id, specificity, catalyst_score, risk_score, cohesion, total_score, letter_grade, graded_at)`
- `prices (ticker, price_date, close, fetched_at, source)`
- Three new indexes for ticker/grade/price lookups.
- Backward-compatible — existing tables / data are untouched.

**Power BI assets**
- `powerbi/export_to_powerbi.py` — three new export functions:
  `export_fact_narrative_tickers` (with entry_close / last_close columns
  pre-joined from `prices`), `export_fact_narrative_grades`,
  `export_fact_prices`. Wired into `main()`.
- `powerbi/dax_measures.dax` — appended `Ticker Mention Count`,
  `Long Mentions`, `Long Mentions L30D`, `Long Mentions L90D`,
  `Distinct Tickers`, `Conviction Weighted Score`, `Avg Total Grade`,
  `A-Grade %`, `Total Position $`, `Cumulative P&L $`, `Avg Return %`,
  `Win Rate`.
- `powerbi/power_query.m` — appended type-changed M scripts for the
  three new CSVs.
- `powerbi/report_layout.md` — appended **Page 6 (Ticker Leaderboard)**
  and **Page 7 (Mentions Over Time)**, plus the calculated columns
  needed on `fact_narrative_tickers`, plus the recommended pipeline
  refresh sequence.

**Dependency**
- `requirements.txt` — `yfinance>=0.2.40` added under the optional
  block (only needed for the P&L step).

## What this audit deliberately did NOT change

- `redhood_aggregator.py` — the core feed-ingestion + LLM extraction
  flow. Risky to touch and unrelated to the audit's scope.
- `redhood_regime_detector.py` — separate concern.
- `accounts_db.py` — separate concern.
- `run.ps1` — could be extended to call `score_narratives.py` after
  each aggregation, but I left that as a deliberate one-line edit for
  you to make once you've reviewed.
- `redhood.db` — no rows were modified. The schema migration is purely
  additive: new tables only.

## How to use the audit pipeline

```bash
# Once: install the optional dep
pip install yfinance --break-system-packages

# Each run:
python redhood_aggregator.py --hours 24      # 1. Pull feeds, extract narratives
python score_narratives.py                   # 2. Grade + extract long tickers
python redhood_pnl.py --report               # 3. Refresh prices + compute P&L
python powerbi/export_to_powerbi.py          # 4. Emit CSVs for Power BI
# Then: open Power BI Desktop → Refresh
```

To wire scoring into your existing PowerShell flow, append to `run.ps1`:

```powershell
python score_narratives.py
python redhood_pnl.py --report
python powerbi/export_to_powerbi.py
```

## Caveats worth saying out loud

- **The grader is heuristic.** It uses regex + keyword lists, not an
  LLM. It mirrors the manual rubric I used in the Excel ledger, and
  the bundled self-test verifies exact ticker matches against the 17
  representative hypotheses. False positives / negatives are
  possible on unusual phrasings — re-run `--self-test` periodically.
- **Until prices are wired in, "winners" measures conviction of the
  extractor, not of the market.** Mention frequency × conviction is a
  ranking signal, not P&L. Run `redhood_pnl.py` early.
- **The pbix file's single page is not the full report design.** The
  `report_layout.md` describes 5 (now 7) pages. If the rendered pbix
  diverges from the design, that's a build-out task for Power BI
  Desktop, not a model issue.
